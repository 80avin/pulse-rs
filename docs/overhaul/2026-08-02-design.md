# Pulse Overhaul — Design & Phased Plan (2026-08-02)

Status: **Approved direction** (user selected all recommended options on 2026-08-02). Companion: `docs/overhaul/2026-08-02-analysis.md` (full issue catalog with file:line evidence).

## 0. Decisions locked in

| Decision | Choice |
|---|---|
| Backend strategy | **Harden in place** — fix correctness, remove dead code, add tests. Keep the actor/tagger/IPC architecture. |
| Frontend strategy | **Rebuild shell + design system, keep stores** — ONE responsive shell replacing the Desktop/Mobile bifurcation; fix the store layer's races. |
| UI foundation | **shadcn-svelte-style kit on bits-ui + Tailwind v4** — standard design language, accessible primitives, token-driven theming + density. |
| Title bar | **Native OS title bar; delete the fake traffic-light chrome.** |
| Sequencing | **Stabilize → redesign → roadmap**, each phase shippable. |

## 1. Goals

1. Fix every confirmed correctness/data-loss/crash bug (Phase 1).
2. Eliminate the duplicated-UI class of defects (two shells, two menus, two toolbars, two search impls, two filter UIs) with a single responsive shell on a coherent design system (Phase 2).
3. Restore standard OS behaviour: native title bar, one context-menu model, consistent keyboard shortcuts, accessible touch targets (Phase 2).
4. **Decide the AI fate: remove the low-quality on-device ML stack; keep the deterministic rule engine; define a pluggable tagger interface so a future BYO-hosted-model adapter slots in cleanly (Phase 1 + Phase 3).**
5. Ship the roadmap features on a stable base: user tags/notes on saved items → onboarding/discovery → BYO model adapter → new feed sources (Phase 3).
6. Establish a real test baseline at each phase, guided by an explicit test policy (see §8).

## 2. Non-goals (deliberate exclusions)

- No greenfield rewrite of pulse-core; the actor/tagger/pagination architecture stays.
- No backend rewrite of the storage layer (sqlx stays; docs updated to match reality).
- **On-device ML tagging (FastText/MiniLM/CLIP) is removed in Phase 1** — low output quality, high complexity. No new on-device model work. The deterministic rule engine stays. Semantic tagging returns only via a BYO hosted model (Phase 3, own design).
- No cloud; the discovery server (Phase 3) is strictly opt-in, anonymous, privacy-preserving.
- No perf optimization beyond what fixes bugs (FastText load speed is fixed because it widens the A1 race, not for micro-benchmarks).
- Phase 3 scope is a *proposal* — it gets its own brainstorm/design before implementation.

## 8. Test policy

Tests are a tool, not a metric. Write a test when it protects a real behavior from regression at acceptable cost.

**Write tests for:**
- Every confirmed bug, at the moment it is fixed (regression-first) — this is the highest-value test.
- Pure-logic modules that are cheap to test and expensive to break: scheduler backoff math + task lifecycle, migration idempotency, adapter URL parsing (Reddit `.rss`), the XSS sanitizer, CLI exit codes + `--json` schema + prefix resolution, and the timeline-store race (both user bugs, as vitest store tests).
- Critical invariants documented in AGENTS.md (single-writer actor, atomic upserts, note-clear semantics).

**Do NOT write:**
- Tautological tests (the `tag_quality` "≥60% coverage" test that mathematically always passes — delete it, don't fix it).
- Vacuous assertions (`must_not_have: ["discussion"]` for a tag nothing can produce — fix the fixture or remove the assertion).
- Tests for dead code (e.g. the `ai/*` modules being deleted in P1.11 get no tests).
- UI rendering minutiae, animation/visual assertions, 100%-coverage chasing.
- Integration tests that need network or a sandbox-disabled environment as a hard requirement — prefer offline, deterministic fixtures (a temp DB, canned HTML, recorded feed payloads).

**Sequencing:** regression tests land with each fix (P1), the risk-priority test suites (scheduler, migrations, adapters, stores, sanitizer, CLI) land with the related work item, and the test harness (vitest, CLI integration) is set up early in P1 so every later fix carries its test.

## 9. Risk register

| Risk | Mitigation |
|---|---|
| Scheduler refactor breaks live sync | Ship with scheduler lifecycle tests + a sync dry-run mode; small diffs |
| Frontend redesign regresses Android | Phase 2 gated on `pnpm tauri android build` + on-device manual pass |
| XSS fix breaks legit feed HTML (images/video) | Allowlist sanitizer with tests; graceful fallback to plain text for unsupported |
| Epoch-guard fixes hide deeper race | Store tests reproduce both user bugs before/after; property-style sequence tests |
| Phase 3 scope creep | Each feature separate design doc; explicit non-goals |

### Mobile save bug — ROOT CAUSE FOUND & FIXED (2026-08-02)
The mobile save button double-fired: `MobileReader`'s save button called `toggleSaved` in BOTH `ontouchend` (`endSavePress`) AND `onclick`, so a single tap toggled twice (save → unsave). This explains all reported symptoms (toast shows, button reverts, saved filter misses the item). Desktop had no touch handlers, so it worked. Fix: `endSavePress` no longer toggles (plain taps are handled by `onclick` alone); long-press sets `suppressNextClick` to block the ghost click that would otherwise double-toggle on top of the note-sheet flow. ItemRow already had a saved bookmark indicator (meta row) — it never showed because items weren't actually being saved.

WIDE (>= ~768px)                    NARROW (< ~768px)

3. **One filter UI:** FilterStrip (mobile tabs) and FilterPills (desktop pills)

4. **One search:** desktop inline FTS search and SearchView merge.
5. **One action menu:** done (popup/sheet from a single source, ItemActionsMenu).
6. **Native title bar:** done (fake chrome removed).
7. **One cheatsheet + consistent keyboard model** (desktop shortcuts stay;
   mobile gets the same actions via bottom sheet).

### Review-pattern checklist (permanent, user-directed) — 2026-08-02
Every frontend review must also hunt these classes:
- P6 **Layout containment**: any `position: fixed`/`absolute` overlay (menu,
  sheet, dialog, popover, toast) rendered inside a transformed/overflow/
  `filter` ancestor (virtualizer rows use `transform: translateY` → breaks
  fixed positioning and scrolls with content), OR per-instance render (a
  menu/dialog mounted per row/item instead of once app-wide). Fix pattern:
  single shared store + render once + bits-ui `<Portal>` into body.
- P7 **Interaction feedback**: controls without hover/press/focus/touch
  feedback, or manual `onmouseenter` bg handlers duplicating the global CSS
  layer. Fix pattern: global `@layer components` hover/press/tap rules +
  delete redundant JS handlers.
